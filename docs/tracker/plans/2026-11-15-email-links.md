# Email: HTML mail, sign-in and reset links — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server emails HTML sign-in and password-reset **links** (banner included) through the HomeLab relay, and the web app has the pages those links open.

**Architecture:** `SmtpMailTransport` renders a multipart (text + HTML + CID banner) message whose button points at `PUBLIC_URL/email-signin#token=…` or `/reset-password#token=…`. Those two new web pages read the fragment, clear it from the address bar, and POST the existing `/api/auth/magic-link/redeem` after a button press. No new backend endpoint; the token never reaches a log or Referer. Short codes (`vtt-admin user code`, the app's typed box) are untouched.

**Tech Stack:** TypeScript, Express, nodemailer, vitest; React 19 + Radix (web); ImageMagick for the one-off banner script.

**Spec:** [2026-11-15-email-and-invites-design.md](../specs/2026-11-15-email-and-invites-design.md)

## Global Constraints

- TypeScript only; per-module folders `components/ hooks/ consts/ types/ lib/` (CLAUDE.md §4). No monolithic files.
- Self-host-first: SMTP stays optional; with `SMTP_URL` unset nothing changes (`NoMailTransport`, Admin CLI codes).
- Never log a token or an email address in a failure line (the existing transport's rule).
- The `/api/auth/magic-link` reply stays identical whether or not the account exists.
- Sign-in link TTL 15 min (`MAGIC_LINK_TTL_MINUTES`), reset link TTL 60 min (new `RESET_LINK_TTL_MINUTES`).
- Light/dark follows the OS in the web pages; the email carries a `prefers-color-scheme` block.
- Banner: one 600×200 progressive JPEG, ≤ 40 KB.
- Update docs and `CHANGELOG.md` `## [Unreleased]` in the same change. Do not cut a release.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- A mail scanner GETs the link: the token must not be consumed (fragment + click).
- `PUBLIC_URL` with a trailing slash or a sub-path must still produce one clean URL.
- Display names or emails containing `<`, `&`, `"` must be escaped in the HTML.
- An old sign-in link used twice, or after expiry, shows a clear "ask for a new link", not a blank page.
- A reset link opened while already signed in as someone else must still reset the intended account.
